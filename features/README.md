# 功能单元目录

## 维护规则

- 本目录下的模块文档记录功能单元、功能关系、实现符号与行为场景的测试关联。
- `F-<模块码>-<序号>` 是永久唯一的功能单元 ID；`S-<序号>` 在所属功能单元内唯一。
- 模块按逻辑职责划分，包含面向用户的功能和跨模块内部能力。
- 实现与测试引用适用于任意语言，统一写作 `项目相对路径::定位符`；定位符使用项目语言或框架可识别的稳定名称。
- `功能关系` 表只填写当前功能主动发出的 `依赖` 或 `触发` 关系及目标 `F-ID`。
- `行为场景` 表的 `测试` 列填 `项目相对路径::测试节点`，多个测试用 `,` 分隔，暂无自动化测试填 `-`。测试是否通过以实际运行结果为准。
- 单次开发计划、测试执行日志、测试台账、审计记录和 Agent 行为规约不写入本目录。
- 创建提交记录首次实现功能的提交，统一写 7 位十六进制 hash；前缀不再唯一时加长到能唯一定位。已有功能不倒查历史。

## 定位符约定

- 整个文件即一个测试入口或组件模块时，定位符写 `<module>`，例如 `scripts/test-sync-ui.mjs::<module>`、`src/lib/SyncPanel.svelte::<module>`。
- 类成员写 `类名.成员名`，模块内联测试写 `tests::函数名`，描述式用例写 `describe > it` 的完整名称。
- 参数化用例（`it.each`、`%s` 模板）写参数展开后的用例名，便于直接定位所验证的样例。
- 场景引用多个测试时用半角逗号加空格分隔；定位符自身的半角或全角逗号、单元格内的竖线分别写作 `\,`、`\，`、`\|`。
