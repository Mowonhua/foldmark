# 发布与更新

Foldmark 的 Windows x64 安装包发布在 [GitHub Releases](https://github.com/Mowonhua/foldmark/releases)。`v0.1.0-alpha.1` 是首个预发布版本。

在「更多操作 → 检查更新」打开更新面板。默认启动时检查并在后台下载新版本，这两个选项可以分别关闭。下载就绪后可从底栏「更新已就绪」打开面板，点击「安装并重启」。安装前会保存全部文档和配置，保存失败时保留应用并允许重试。

## 更新频道

桌面应用通过 HTTPS 获取 Tauri 更新清单。预发布版本读取 [preview.json](https://raw.githubusercontent.com/Mowonhua/foldmark/updates/preview.json)，正式版本读取 [stable.json](https://raw.githubusercontent.com/Mowonhua/foldmark/updates/stable.json)。在首次正式发布之前，`stable.json` 尚不存在。

预发布只更新 preview；正式版同时参与 stable 和 preview。每个频道仅接受 SemVer 更高的版本：补发旧版本不会使频道倒退，同版本重跑不会替换已经公开的安装包。较新的预发布存在时，较旧的正式版仅更新 stable。

`updates` 是工作流维护的独立分支，每次通过一个 commit 原子更新频道文件。清单指向固定版本的 Release 下载地址；应用安装前使用内置公钥验证签名。[Tauri 更新机制](https://v2.tauri.app/plugin/updater/)要求签名，`.sig` 文件内容必须完整保留。

## 首次配置

在本机仓库目录运行 Tauri 签名工具，将密钥写到仓库之外的保管目录：

```powershell
npx tauri signer generate -w "$env:USERPROFILE/.tauri/foldmark.key"
```

将 `.pub` 公钥文件的完整内容写入 `src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`。私钥和密码分别写入 GitHub 仓库的 Actions secrets：

| Secret | 内容 |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | 私钥文件的完整内容 |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 生成密钥时使用的密码；无密码时可省略 |

私钥需要单独备份。已安装版本内置对应公钥，后续更新必须继续使用该密钥签名。这里的签名用于应用内更新验证；Windows Authenticode 证书签名需要另外配置。

工作流使用仓库自带的 `GITHUB_TOKEN` 发布资源和更新分支，`publish` job 声明 `contents: write`。Actions 必须获准运行，仓库规则须允许工作流创建和更新 `updates` 分支。第三方 Actions 均固定到具体 commit。

## 发布一个版本

1. 同步修改 `package.json`、`package-lock.json` 中根包的两处版本、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 和 `src-tauri/Cargo.lock` 中 `foldmark` 包的版本。
2. 在 `docs/releases/v<版本>.md` 写明用户可见变化、安装方式和已知限制。
3. 运行验证并提交。提交格式为 `<type>: 中文标题`，空行后写中文改动列表。
4. 推送 main 和与版本完全一致的标签。例如：

```powershell
node scripts/release.mjs validate v0.1.0-alpha.1
node --test scripts/release-policy.test.mjs scripts/release.test.mjs scripts/release-github.test.mjs
npm run check
npm test
npm run test:app
cargo test --locked --manifest-path src-tauri/Cargo.toml --lib
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
npm run build
git push origin main
git tag v0.1.0-alpha.1
git push origin v0.1.0-alpha.1
```

推送 main、拉取请求和手动运行 CI 都会执行前端、Rust 和发布规则检查。推送 `v*` 标签后，Release 工作流先复用同一套检查，再执行 `npx tauri build -- --locked` 生成签名 NSIS 安装包。第二个 `--` 将 `--locked` 传给 Cargo，不能将它直接作为 Tauri 参数。

每次 Release 包含以下四项资源：

| 文件 | 用途 |
| --- | --- |
| `Foldmark_<版本>_x64-setup.exe` | Windows x64 安装包及自动更新载荷 |
| `Foldmark_<版本>_x64-setup.exe.sig` | Tauri 更新签名 |
| `latest.json` | 当前版本的更新清单 |
| `SHA256SUMS` | 前三项资源的 SHA-256 摘要 |

工作流先建立草稿并上传文件，下载校验全部资源后公开 Release，再次下载校验后才提升更新频道。带 `alpha`、`beta`、`rc` 等 SemVer 预发布标识的标签会设置为 GitHub prerelease，不占用 Latest 正式版入口。构建完成但 Release 仍是草稿、工作流仍在运行或频道文件尚未晋升时，发布尚未完成。

## 失败与重跑

版本或标签不符时，修正文件并使用正确的新标签。签名构建失败时先检查两个 secrets 是否对应内置公钥。资源下载或摘要检查失败会阻止频道晋升，现有用户仍读取之前的完整版本。

在 GitHub Actions 中重新运行失败的 Release 工作流即可重试。草稿中的资源允许重新上传；已经公开的 Release 只读取和验证既有资源，再补做频道晋升。频道分支发生并发修改时，非强制更新会拒绝覆盖，重新运行会重新读取频道。

需要本地检查签名构建结果时，可使用独立输出目录整理资源；该命令只读写本地文件：

```powershell
$env:GITHUB_REPOSITORY = 'Mowonhua/foldmark'
$env:RELEASE_DIR = Join-Path $env:TEMP 'foldmark-release-preview'
node scripts/release.mjs prepare v0.1.0-alpha.1
```
