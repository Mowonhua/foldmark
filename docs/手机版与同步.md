# Android 与局域网同步

Foldmark 在 Windows 与 Android 上编辑 Markdown。每个设备先保存本机文件，再与已配对设备交换版本。没有网络时，编辑、任务归档和搜索仍可使用。

## 手机文件

手机把文档保存在应用私有目录。导入文件会创建副本，后续编辑不会回写导入来源。“另存副本”通过系统文件选择器导出 Markdown。

手机“删除项目”会删除该项目的私有 Markdown 文件和恢复草稿，不删除导入来源或电脑文件。电脑“移除项目关联”保留原文件。

手机使用单栏编辑界面。项目导航与大纲放在抽屉中。编辑辅助栏提供任务插入、缩进、排序、撤销和重做。长按正文使用系统选字菜单。

编辑辅助栏使用图标按钮，并保留读屏名称。同步页面的文档区独立滚动，连接设置固定在底部，按需展开。

主题、字号、阅读位置和设备路径各端独立保存。手机不显示桌面更新器、窗口控制和置顶卡片入口。

## 配对与文档选择

1. 把电脑和手机接入可互通的同一局域网，打开两端 Foldmark。
2. 在电脑“更多操作 → 设备同步”中显示配对二维码。
3. 在手机“设备同步”中扫描二维码，再在电脑允许连接。二维码有效期为五分钟。
4. 在同步面板勾选需要同步的项目或灵感簿。
5. 对端出现待接收文档时，点击“接收文档”，选择新建项目或关联本机已有项目。电脑新建项目需要选择新文件的保存位置。关联已有项目时，内容不同会进入合并界面，确认前保留双方正文。

相机不可用时，可在电脑复制配对信息，再在手机手动输入。电脑地址发生变化后，手机尝试在局域网发现已配对电脑。自动发现失败时，可在手机输入电脑的 IPv4 地址和端口。

电脑存在 VPN 或多个网卡时，二维码下方可选择手机能够访问的电脑地址。首次连接失败也会尝试局域网发现；候选地址仍需通过固定证书验证。

一个设备只能保留一个配对对象。解除配对不会删除 Markdown 文件。重新配对后，需要重新选择同步文档。相同文件名不会自动建立文档关联。

解除或更换配对前，旧的同步记录保存在应用数据目录的 `sync/detached-*.json` 中，其中包括尚未接收的正文与未解决的冲突版本。该副本不再参与同步，可用于手动恢复内容。

## 同步内容与时机

同步包括所选项目的正文、项目名称、项目归档状态，以及灵感簿正文。同步不搬动电脑原文件，不传输本地图片和附件。原文中的资源引用保留；手机没有对应资源时，不能显示或打开该资源。

手机在前台时主动建立经过配对认证的 TLS 长连接。两端输入防抖四百毫秒后触发同步：手机直接交换版本，电脑通过同一连接通知手机立即交换。正文、版本确认与心跳复用这条连接。空闲时每十五秒补充交换一次，覆盖没有触发编辑事件的外部文件修改。

手机离开应用后关闭长连接并释放局域网发现资源，回到前台立即重连和交换。离线或连接失败时逐步延长重试间隔，最长十五秒。电脑需要保持 Foldmark 运行；手机不运行后台常驻同步服务。

“已保存”表示正文已写入本机。“已同步”表示当前同步版本已经得到对端确认。“等待同步”“等待对端确认”或错误状态均不能视为传输完成。

接收对端当前版本并成功保存后，本机立即确认该版本。手机接收电脑的新版本或生成合并版本后，立即再交换一次，让电脑获得确认；新生成的合并版本须得到对端确认后才显示“已同步”。

移除项目关联、取消同步选择或解除配对不会删除对端文件。文件缺失、保存失败或存在待恢复草稿时，该文档暂停交换，其他文档继续同步。

取消选择后，下一次成功交换会撤回对端尚未接收的文档；对端已经接收的文件保留。选择清单带有持久化序号，旧请求重传不能恢复已撤回的接收提示。临时读文件失败不等于取消选择。

## 冲突与恢复

同步使用文档标识和共同版本，不比较设备时钟。只有一端修改时接收该端版本；双方修改不相交段落时自动合并。

以下情况保留双方内容，并显示“比较并处理”：

- 修改重叠，或项目资料存在不同改动。
- 一端修改任务结构，另一端也修改正文。结构变化包括任务归档、排序和删除。
- 双方没有可用的共同版本，例如首次连接时已有不同灵感簿。

合并界面可选用本机、选用对端或编辑合并结果。选择前保留双方版本，不向正文写入冲突标记。处理期间正文再次变化时，旧的解决请求失效，需要重新比较。

写入日志先于正文保存。传输中断或应用退出后，Foldmark 比较实际文件与日志，再恢复同步。无法确认文件状态时保留冲突，不盲目重放。已确认一致的版本成为历史截点，活动记录不持续累积全部正文副本。恢复早于截点的旧备份可能需要人工合并。

同步协议限制单份正文为 1 MiB、单次消息为 8 MiB、单次文档数为 200。超过限制时拒绝传输并保留本地文件。协议不兼容时提示升级，不写入对方数据。

文档交换协议版本为 3，支持增量版本和正文补丁，并要求双方发送完整选择清单。双向长连接要求两端一起升级；原有配对和本机保存记录可继续使用。

## 连接边界

电脑监听局域网端口，手机主动建立双向长连接；建立后双方都能主动发送消息。二维码固定电脑证书，长期凭证只保存在本机应用数据目录。局域网发现结果只能提供地址，不能替换设备身份。未经配对、凭证已撤销或证书不符的连接不能交换文档。解除配对或修改地址会关闭旧连接；旧连接退出不能关闭新建连接。

首版不提供公网穿透、云端中继、后台常驻同步或多人协作。

## 手机导航与更新

从屏幕左侧 50% 范围内向右滑动可打开项目导航，在侧栏内向左滑动可关闭。纵向滚动、右半屏横向手势和选字不触发导航。菜单、搜索和顶部项目列表在外部按下时关闭。手机菜单不提供快捷键弹窗。

手机默认在启动时检查更新并自动下载，可通过“更多操作 → 检查更新”修改偏好或手动检查。更新源为 `Mowonhua/foldmark` 的 GitHub Releases，只选择较新且带 arm64 APK 的稳定版。没有 APK 的发布和预发布版本不进入手机更新候选。

检查和下载遇到连接中断会自动重新建立连接重试，并从已写入位置继续下载；服务端不支持续传或资源已变化时从头重下。重试仍失败时显示网络中断提示，可在更新面板再次重试。

安装包下载后检查大小、应用标识、发布版本、递增版本号和签名。只有与当前应用签名一致的安装包才能安装。点击“安装更新”会先保存全部文档和配置，再打开 Android 系统安装器。首次安装需在系统设置中允许安装来源，返回应用后点击“重试”。用户取消系统安装后可再次安装，应用继续允许编辑。

## 构建与验证

Android 构建需要 JDK 17、Android SDK Platform 36 与 37.0、Build Tools 37、NDK 27.2.12479018，以及 Rust 的 `aarch64-linux-android` 目标。设置 `JAVA_HOME`、`ANDROID_HOME` 和 `NDK_HOME` 后运行：

```powershell
npm ci
rustup target add aarch64-linux-android
npm run tauri -- android init --ci
node scripts/configure-android.mjs
npm run tauri -- android build --apk --target aarch64
```

正式 APK 使用独立签名密钥。密钥和密码应放在仓库之外；后续升级使用相同签名。设置 `FOLDMARK_ANDROID_KEYSTORE` 为密钥文件路径，设置 `FOLDMARK_ANDROID_PASSWORD_FILE` 为密码文件路径。密钥别名缺省为 `foldmark`，可通过 `FOLDMARK_ANDROID_KEY_ALIAS` 修改。

Windows 可运行 `powershell -File scripts/build-android.ps1` 构建并验证签名，输出位于 `dist-android/`。追加 `-Install -Device <adb设备地址>` 可安装到指定设备。

手机更新要求对应 GitHub Release 附带使用相同密钥签名的 `Foldmark-<版本>-arm64.apk`。使用已登录的 GitHub CLI，运行 `powershell -File scripts/build-android.ps1 -Publish` 可构建并上传到已存在的同版本 Release；不会覆盖已经公开的同名资源。从 v0.7.1 起，标签发布流程自动构建并验证 Android arm64 签名 APK，与 Windows 资源一起校验后公开 Release。签名 secrets 的配置见[发布与更新](发布.md#android-签名配置)。

运行 `npm run check`、`npm test`、`npm run test:app` 和 Rust 测试检查共享代码。开发服务器运行后，执行 `node scripts/test-mobile-browser.mjs` 检查触屏布局及编辑入口。

执行 `node scripts/test-mobile-navigation.mjs` 检查三个浮层的外部关闭、手机更新入口及抽屉左右滑动。Android 系统安装授权、包签名校验和覆盖安装的数据保留需要真机验证。

执行 `node scripts/test-sync-ui.mjs` 检查两端同步页面的状态、滚动与主题布局。该脚本使用开发服务器中的专用验收入口，不连接真实设备。

执行 `node scripts/test-sync-scroll.mjs` 检查接收对端版本后阅读位置不变。脚本在手机尺寸的真实编辑器中替换正文，核对视口顶部原文行与像素偏移。

`scripts/test-paired-recovery.mjs` 验证真实手机在确认前退出后的重传。它只接受标识为 `app.foldmark.syncvalidation`、启用本机 CDP 端口 9223 的桌面验收实例，以及 `test-results/` 下的专用文档。调用参数依次为 ADB 路径、设备地址、同步文档标识和新的文本标记。脚本开始等待后，在手机对应文档中输入该标记。脚本延迟电脑的确认、终止并重启手机应用，核对两端最终确认、正文及文件修改时间，并恢复临时拦截。

浏览器检查不能替代 Android 真机验收。真机需验证中文输入法、软键盘、长按选字、系统导入导出、相机权限、局域网连接、前后台切换及进程终止后的恢复。
