## 首版基线已修复的问题

- Svelte 深层代理使当前会话与保存闭包引用不同 EditorState，出现界面已完成而文件不变：改用共享原始会话引用，App 落盘与重启测试已覆盖。
- 已勾父项包含未完成后代时整组隐藏：统一有效归档判断，待办、搜索和统计共用模型语义。
- 旧外部读取在新保存后返回、或多个读取乱序：以读取代次和基线身份防止回退。
- 恢复快照纯防抖会被连续输入无限推迟：改为周期性读取最新文本的节流。
- 保存期间收到的外部变化被跳过后不再检查：保存链结束自动补查。
- 保存失败仍移除关联，丢弃唯一内存草稿：移除流程要求保存成功。
- 全部待办菜单可以编辑隐藏的最近项目：聚合视图不再提供这些编辑动作。
- 过期打开请求失败覆盖新项目、跨项目完成提示撤错编辑、聚合页面的“包含归档”无效：均已有 App 回归。
- 搜索超过 100 条无定位入口、配置写失败仍允许关闭窗口：增加加载更多与配置保存退出门槛，已有 App 回归。
- 失效路径重新定位时本地草稿与目标文件不同：先保存待恢复文本并展示双方，只有明确选择恢复后才写入目标，已有 App 回归。
- 仅用视觉替换隐藏正文，箭头进入隐藏区，Backspace/Delete 损坏隐藏正文或连接分隔：共用原子导航范围并单独保护空选区删除；非空选区仍按用户选择操作原文。

这些项目不能用“处理了 isComposing”“存在 CSS”“有安装包文件”等代码事实代替通过结果。

2. **真实指针排序**：浏览器已实测折叠任务连同公式正文、已完成后代整体移动和一次撤销，无误触完成。普通/有序控件、无效区域、Esc、阈值和自动滚动有自动化覆盖，仍可在 Windows WebView2 中继续完整组合验收。
3. **焦点与布局稳定**：完成当前/其他任务、连续快速勾选、折叠父子项、搜索隐藏内容、加载本地图片和公式后，检查光标、控件命中和滚动锚点。

- [受限增量投影对比](performance-incremental-model.json) 使用与浏览器相同的 576,584 字节、5,000 任务混合文档。两条路径接收完全相同的已更新 Lezer 完整树，20 个正式样本交替先后执行，且每个样本都在计时之外逐字段核对模型：完整投影 P95 9.247 ms，受限映射 P95 1.692 ms。优化仅覆盖单个任务首行内容中的 Unicode 字母、数字和 ASCII 空格；代码、公式、结构标记、换行、多处编辑或容器边界核验失败一律完整投影。48 项差分与拒绝测试包含 350 次确定性随机增删及混合行内语法。
- [原生记录](native-validation.json) 使用一个 87 字节清单记录运行中的 Tauri/WebView2 进程组。该记录明确排除冷启动、最终安装包和 20 项目/5,000 任务验收，不设未确认的内存通过阈值。
- [浏览器交互记录](performance-browser.json) 与 [增量优化前的同场景记录](performance-browser-before-incremental.json) 分开保存。生产页面使用 576,584 字节、5,000 条任务和 19 个后台索引项目，真实字母键输入与 Space 激活复选框各 20 次。输入至文档提交 P95 为 11.0 ms、至下一 rAF 为 12.6 ms；键盘完成至下一 rAF 为 31.7 ms。报告文本框在采样期间冻结，避免测量页面自身的大文本布局干扰输入。记录包括所有原始值、排除项、浏览器版本与产物指纹。下一 rAF 不等于最终像素呈现，Chromium 测量也不直接等于 Windows WebView2 结果。
- 方案中的 P95 输入 <16 ms、勾选反馈 <50 ms、约 1 秒冷启动尚需相应完整边界证据。平均值、同步事务耗时、已运行数分钟进程的内存不能替代这些目标。
