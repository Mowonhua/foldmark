## 开发与构建

需要 Node.js、npm、Rust，以及 Windows 的 MSVC C++ 构建工具。桌面运行需要 WebView2。

```powershell
npm ci
npm run tauri -- dev
```

只预览前端：

```powershell
npm run dev
```

浏览器预览使用独立的浏览器存储，导入的是文件副本，可通过菜单另存 Markdown；实际原文件关联和系统文件监听需要桌面应用。

## 画布实现

画布使用 [`@excalidraw/excalidraw`](https://github.com/excalidraw/excalidraw) 作为渲染与交互引擎。依赖包声明 MIT 许可证。应用以独立的 React 根挂载引擎，Svelte 组件负责全页界面、主题和保存屏障。

正文使用 `canvas` 代码围栏保存版本化 JSON。`src/lib/canvas/model.ts` 校验快照并提取附件引用。`src/lib/editor/canvas.ts` 将卡片连接到当前源文范围；会话通过原文基线校验后才替换完整快照。外部改写、删除或文档切换使旧会话失效。源码视图保留原文，损坏和不支持的格式不降级写回。

收起的卡片通过 `src/lib/canvas/thumbnail.ts` 绘制 SVG 文字、图形和连线，不加载完整引擎。可见卡片按附件引用去重、串行读取图片；控件卸载时释放 Blob URL，过期读取不再创建资源。`Preferences.canvasPreview` 控制两行、六行、十二行的阅读布局，缺省紧凑，只保存到本机配置。更多操作和右键插入菜单共用控制器的画布命令。

`CanvasPanel.svelte` 在展开后动态加载 `engine.ts`。引擎接管缩放、平移、选区和内部撤销；阅读位置只保存在内存，不写入正文或同步数据。

`CanvasSaveQueue` 合并高频场景变化，拖动期间不提交中间帧。队列先通过 `CanvasAssetPort` 保存图片，再提交正文引用；文档保存器负责最终落盘。原生端以内容摘要命名，在同目录 `.assets/` 中保存不可变附件。浏览器端使用 IndexedDB。删除图形不触发附件清理。

`src/lib/canvas/bundle.ts` 通过 ZIP 搬运 Markdown 和实际引用的附件。导入器先校验包结构、路径和摘要，再保存附件；全部成功后才返回正文。`CanvasEngine.exportPNG` 导出白色背景 PNG，最长边限制为 4096 像素，不嵌入可编辑场景。

画布字体不依赖远程 CDN。`vite.config.ts` 中的 `canvasRuntimeAssets` 插件在开发服务中提供同源字体，并将 WOFF2 文件写入构建产物的 `canvas-assets/fonts/`。Helvetica 字体映射使用 [本地字体](../third_party/canvas-fonts/LiberationSans-Regular.source.json)，其余字体来自引擎依赖。引擎通过 `window.EXCALIDRAW_ASSET_PATH` 指向本地目录，字体按需加载。[许可及来源](licenses/canvas/) 随构建产物写入 `canvas-assets/licenses/`。

画布规格及测试关联见 [Markdown 画布](../features/canvas.md)。仅运行画布与编辑器验证：

```powershell
npx vitest run src/lib/canvas src/lib/editor/canvas.test.ts
```

浏览器布局、图片导入、PNG 导出与全页交互需要真实浏览器验收。单元测试中的 jsdom 不提供真实布局或 Canvas 渲染。

## 安装包构建

构建 Windows NSIS 安装包：

```powershell
npx tauri build --config '{"bundle":{"createUpdaterArtifacts":false}}' -- --locked
```

以上命令用于本地构建，不生成更新签名。输出为 `src-tauri/target/release/bundle/nsis/Taskrail_0.1.0-alpha.1_x64-setup.exe`。正式发布由 GitHub Actions 生成签名安装包、更新清单及 SHA-256 校验文件，步骤见 [发布与自动更新](发布.md)。

安装包采用 WebView2 下载引导方式；机器缺少运行时时，首次安装需要联网下载。需要离线安装的设备应预先安装 Microsoft WebView2 Evergreen Runtime。应用正文、搜索、公式和保存均在本地工作。

## 应用图标

图标源文件为 [`assets/brand/taskrail.svg`](../assets/brand/taskrail.svg)。深绿色圆角方形中的米白色 T 使用双竖轨道，表示多个项目。源图保留 `background` 背景矩形和独立的标志路径，前景与圆形版本从同一份源图派生。

修改源图后运行：

```powershell
npm run icons:generate
```

命令更新 Windows PNG、ICO，以及 Android 五档密度的普通、圆形、自适应和单色图标。浏览器标签页、应用侧栏和 README 共用 `src-tauri/icons/icon.png`。Android 自适应图标分别使用前景、背景和单色图层；普通与圆形启动图标单独导出，保留完整标志。

脚本只替换图标资源，不修改应用标识、配置路径或签名。更新 README 界面截图时，应从使用新图标的应用中重新截图。

## 验证

界面翻译入口、语言回退及新增语言步骤见 [多语言](多语言.md)。

```powershell
npm run check
npm test
npm run test:app
cargo test --manifest-path src-tauri/Cargo.toml --lib
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
npm run build
```

`test:app` 使用真实 Svelte App、CodeMirror 和文件适配器，覆盖输入落盘、重启、项目切换、撤销隔离、搜索和失败边界。Rust 测试在真实临时目录验证原子保存、文件冲突、编码换行和监听。

Windows 启动以可执行文件的完整规范路径判重：同一路径重复启动会显示并还原已有窗口，不同目录或文件名的程序分别运行。实例锁限定当前 Windows 会话，应用配置目录继续由 Tauri 应用 ID 决定。

构建后运行原生启动验收（脚本只启动和结束临时复制的程序）：

```powershell
cargo build --manifest-path src-tauri/Cargo.toml
.\scripts\test-single-instance.ps1 -Executable .\src-tauri\target\debug\taskrail.exe
```

Debug 程序需要同时运行 `npm run dev`；也可以将 `-Executable` 指向已构建的 release 程序。验收覆盖并发冷启动、不同路径隔离、工作目录变化、隐藏及最小化还原、最大化保留，以及退出后的再次启动。

性能采样与功能验收分别记录。内核与同步编辑事务耗时不能替代屏幕反馈、原生冷启动或整个 WebView 进程组的内存数据。

```powershell
npm run benchmark:browser:build
npm run benchmark:browser
```
