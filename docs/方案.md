# Foldmark 产品与技术方案

整理日期：2026-09-06。

本文记录产品方向、主要交互、存储选择、技术方案及实施顺序，作为开发依据。使用与构建说明见 [README](../README.md)；文中的性能数值是验收目标，应与实测记录区分。

## 使用场景与产品目标

用户目前在 Markdown 文件中维护待办，并通过 Typora 编辑。任务增多后，已完成事项占据大量篇幅，查找尚未完成的工作需要反复滚动。现有看板工具的多栏结构、创建任务操作和 Markdown 输入体验不符合这一工作方式。

产品定位为面向多项目的 Markdown 待办编辑器：用户连续输入文档，点击复选框完成任务，已完成内容自动退出待办视图，并可以在归档中查阅或恢复。

实际清单包含长段说明、缩进正文、代码块、编号说明和嵌套任务。因此，一条任务需要容纳完整 Markdown 内容，不能限制为标题加一段纯文本描述。

首版优先面向 Windows 桌面，离线完成编辑、搜索、公式渲染和保存。多项目管理属于首版基础能力。

## 项目与文档组织

信息结构为“项目 → Markdown 清单 → 任务及正文”。首版每个项目关联一份主清单，后续可以扩展为多文档。

每个项目包含项目标识、显示名称和主清单路径。用户可以创建项目并关联已有文件，例如将 Dataflow 关联到 `D:\Workspace\dataflow\docs\清单.md`；关联操作不复制或搬动原文件。新项目也可以在用户指定的位置创建清单。

项目导航支持新增、重命名、切换和移除关联。移除项目仅移除应用中的关联，不删除其 Markdown 文件。路径失效时提供重新定位文件的入口，不自动创建空文件覆盖原位置。

每个项目具有以下视图：

| 视图 | 内容与用途 |
| --- | --- |
| 待办 | 展示未完成任务及必要的章节、正文上下文，作为默认编辑入口 |
| 归档 | 展示已完成任务，支持查阅与取消完成 |
| 完整源码 | 展示完整 Markdown 原文，包括已完成任务，适合处理文档结构 |

应用另提供“全部待办”入口，按项目分组展示未完成任务。点击结果定位到所属项目的原任务继续编辑，避免在聚合页面建立第二套编辑状态。新建任务需要明确所属项目。

切换项目时分别保留光标、滚动位置、折叠状态和当前视图。项目数量增多后，可以通过快速切换入口按名称查找项目。跨项目搜索默认覆盖待办，用户可以选择包含归档；结果显示所属项目和章节。

## 编辑体验

默认采用就地预览。光标所在的 Markdown 结构露出必要的语法标记，其他内容呈现排版效果。编辑和预览共享一份文本，切换模式时保留选区与位置。

### 输入与快捷操作

| 操作 | 行为 |
| --- | --- |
| 输入 `- [ ] ` | 显示可点击的任务复选框 |
| 在任务首行末尾按 Enter | 创建下一个同级任务，光标进入新任务 |
| 在任务首行中间按 Enter | 按编辑器的列表拆分规则处理光标两侧文本 |
| Shift + Enter | 在当前任务内换行，并维持列表项需要的缩进 |
| 空任务按 Enter | 退出当前层级的任务列表 |
| 在任务行使用 Tab / Shift + Tab | 调整任务层级，连同所属正文及子任务一起缩进或反缩进 |
| 点击正文 | 原地编辑 |
| 按住列表项原有标记或任务复选框并拖动 | 连同所属正文和子项一起排序 |
| 鼠标移到列表标记或任务复选框前的控制区 | 有可折叠内容时显示三角按钮，点击切换折叠与展开 |
| Ctrl + Z | 撤销最近的文本、排序或完成操作 |
| 输入 `$...$` / `$$...$$` | 分别编写行内公式和块级公式 |

Enter 的行为依赖光标所在的语法结构。在代码块、公式块和任务的正文段落中，保留该结构正常的换行行为，不因为它属于某个任务就强制创建新任务。完整源码模式保留普通 Markdown 编辑方式。

中文输入法组合输入期间，Enter 只负责确认候选词，不创建任务或触发归档。键盘快捷键不能破坏编辑器的选区、复制粘贴和输入法行为。

### 列表与任务的拖动排序

就地预览直接使用条目原有的行首标记作为拖动入口：无序列表使用列表圆点，有序列表使用编号，任务使用复选框。任务复选框同时承载单击完成与拖动排序，不额外添加圆点或独立拖动柄，也不向 Markdown 插入额外字符。

按住列表标记或任务复选框并移动超过拖动阈值后开始排序，显示拖动预览和明确的插入线；松开后提交，按 Esc 或在无效区域松开则取消。单击列表标记不修改文档；复选框在按下时不切换状态，未进入拖动且在复选框内松开时才按单击切换完成状态。一旦进入拖动，无论放置成功还是取消，都不触发完成切换；键盘激活复选框仍正常切换完成状态。拖动过程中靠近编辑区上下边缘可以自动滚动，正文仍支持正常的光标定位与文本选择。

首版支持同一父级、同一列表内的排序，顶层列表项也可以在所属列表内调整顺序；改变层级继续使用 Tab / Shift + Tab。落点只位于同级列表项之间，不允许落入正文、代码块、公式块或自身后代，也不跨章节、跨列表或跨项目搬移。

移动单位是语法树中的完整列表项，包含多段正文、嵌套列表、子任务以及当前折叠或因完成而隐藏的后代。移动保留这些内容及完成状态，只修改必要的源文范围与结构分隔；有序列表遵循 Markdown 的顺序编号语义，预览随新顺序显示编号，不为排序重写整份文档的数字标记。

待办视图中的插入线必须对应源文中明确的同级项边界：落在某个可见项之前就紧邻该项之前，落在末尾就紧邻最后一个可见项之后；隐藏的已完成同级项不参与可见项之间的重新排列，彼此顺序保持不变。被拖动项内部隐藏的内容随整项移动。

排序用于项目待办编辑视图；归档、搜索结果和“全部待办”提供定位回原文的入口，不直接拖动排序。完整源码模式保留普通文本编辑。一次放置形成一笔编辑事务，撤销或重做整体恢复顺序与选区；移动后光标、折叠状态和视口锚点跟随原条目。

### 列表与任务的折叠展开

每个列表标记或任务复选框前预留固定宽度的折叠控制区。鼠标移入该区域或对应行首控件区域时，存在后续正文、续行或子项的条目显示向下三角 `▾`；点击后折叠，再次点击展开。折叠时三角改为向右 `▸` 并持续可见，便于发现隐藏内容；移出展开条目后按钮淡出，但预留空间不变，避免文字横向跳动。只有首行内容的条目不显示折叠按钮。

折叠保留列表项或任务的首行，隐藏其余正文和全部后代，显示简洁的已折叠提示。列表标记和任务复选框仍可操作，折叠状态下拖动仍移动完整条目。折叠与完成状态独立：折叠不勾选任务、不触发归档；展开后仍遵循当前视图的完成过滤规则。

折叠父项时保留各子项原有的折叠状态，再次展开父项时恢复。若光标或选区将被折叠隐藏，先将选区收拢到该项首行；搜索定位到隐藏内容时临时展开必要的祖先，使目标可见。

折叠属于界面状态，按项目与文档保存，不写入 Markdown，也不占用文本撤销历史。应用内编辑与排序通过编辑事务映射条目位置；重启或外部修改后，只恢复能够可靠匹配的条目，其余默认展开，避免把折叠状态错误套用到其他内容。折叠状态不改变搜索范围或任务统计。

列表标记、任务复选框与各自前方的三角按钮使用独立命中区域。三角按钮可通过键盘聚焦，使用 Enter / Space 切换；控件获得焦点时同样显示，不依赖鼠标悬停。菜单提供折叠、展开和同级上移／下移操作，键盘排序遵循与拖动相同的范围和撤销规则。

### Markdown 与公式范围

首版支持标题、段落、强调、删除线、链接、图片、引用、有序和无序列表、任务列表、代码块、表格，以及行内和块级数学公式。Markdown 基础语义采用 CommonMark，并明确启用任务列表、表格和删除线等扩展；公式语法作为额外扩展处理。

任务正文可以包含多个段落和嵌套结构，编辑器负责插入正确缩进。连续写作、跨任务选择、批量粘贴与撤销均基于同一文档实现。

公式编辑时保留源码，结束编辑后原地排版。未闭合或不支持的公式显示局部提示，原文必须完整保留。公式支持范围以 KaTeX 的数学语法为准，首版不承诺完整 LaTeX 文档编译或任意宏包。

原始文本是编辑依据。预览或归档不能顺带重排整份 Markdown，改变空行、缩进、列表标记或代码内容。暂不支持的语法也需要保留原文，并可在源码模式下编辑。

## 完成与自动归档

### 归档语义

首版采用逻辑归档：勾选任务将原文中的 `[ ]` 改为 `[x]`，待办视图隐藏对应的已完成内容，归档视图展示这些内容。归档不搬动 Markdown 中的原始位置，不额外复制任务正文。

因此，重新通过 Typora 打开同一文件时，已完成任务仍在原位置。该选择解决新软件中的浏览问题，同时保留原文件的章节关系、文本格式和 Git 可读性。

若后续需要让原文件本身缩短，可以单独设计“搬移到归档文件”的功能。跨文件保存、撤销、相对链接和恢复位置必须在引入该功能时一起处理，首版不自动执行文件搬移。

### 任务及子任务规则

任务边界由 Markdown 语法树中的列表项决定，不能用逐行正则截取。顶层任务的归档范围包括其所有正文、代码块和子任务；独立于列表项的章节或段落不随任务隐藏。

- 完成顶层任务后，该任务及其所属内容从待办视图移除。
- 完成子任务后，将其收进父任务下的“已完成 N 项”，保留父任务及上下文。
- 父任务仍有未完成子项时，不直接隐藏整组内容。界面提供明确的“完成整组”操作，一次完成父项及所有未完成后代。
- 子任务全部完成不会自动勾选父任务，由用户决定父任务是否结束。
- 归档视图展示已完成子任务时保留父任务路径；父任务也已归档时，按完整父任务展示，不重复列出子项。

`- [ ] ~~文字~~` 仍是未完成任务，删除线只影响文字格式。代码块或行内代码中的 `- [ ]` 不识别为任务。

### 反馈、焦点与恢复

点击复选框后立即显示完成态，再通过短暂过渡收起内容，并显示可撤销反馈。数据状态由编辑事务决定，不能依赖动画播放完成。

滚动位置以相邻的存活内容为锚点。鼠标完成其他任务时，不抢走正在编辑的光标；通过键盘完成当前任务时，光标转到下一个可编辑任务，没有下一项时保留新增任务的位置。连续勾选不能因为列表重排而误中另一项。

一次撤销恢复同一完成操作涉及的全部状态、内容可见性和选区。“完成整组”是一笔事务，撤销时也整体恢复。归档中取消完成后，任务在原位置重新出现；恢复嵌套任务时必须维持可达性，不能让未完成子任务继续隐藏在已完成父项下，必要时一并取消祖先任务的完成状态。

跨项目编辑历史分别维护。切换项目后，撤销作用于当前项目，不能悄悄修改另一个项目。

## 界面与视觉方向

界面以文档阅读和连续输入为中心。左侧提供可收起的项目导航，中央显示当前文档，顶部保留项目、视图切换和搜索入口。

```text
┌──────────────────────────────────────────────────────┐
│ 当前项目                                    搜索  菜单 │
├──────────────┬───────────────────────────────────────┤
│ 全部待办     │ 待办 / 归档                           │
│              │                                       │
│ 项目         │ ▾ □ 任务标题                          │
│   Dataflow   │   多段正文、代码、图片与公式           │
│   个人       │       □ 子任务                        │
│              │                                       │
│ + 新增项目   │ ▸ □ 下一件事...(只保留显示一行，如有后续内容则加上省略号) │
└──────────────┴───────────────────────────────────────┘
```

浅色模式采用暖白纸面、深灰正文和低饱和绿色；深色模式采用炭灰背景，并保持文字和控件对比度。正文默认使用清晰的中文无衬线字体，代码使用等宽字体，允许自定义字体、大小等，不要硬编码写死。

宽窗口中的正文区域建议约 720–860 px，窄窗口自适应收缩。任务通过留白区分，列表项通过原有圆点或编号拖动排序，任务通过复选框拖动排序，通过这些标记前的三角按钮折叠正文与子项。上图中的向下三角表示悬停或键盘聚焦状态，向右三角表示持续可见的折叠状态。常用操作放在快捷键、右键菜单及可发现的菜单入口中，避免工具栏挤占阅读空间。

复选框和菜单支持键盘操作，并保留明确的焦点样式。任务状态同时通过控件和文字表达，不能只依赖颜色。尊重系统减少动态效果设置；图片、公式加载和归档过渡不能使正在操作的任务跳位。

前期交互草图仅用于说明项目切换、勾选归档、撤销和连续新增。视觉方向及完整编辑器行为仍需在实际桌面原型中验证，草图不代表已实现的软件能力。

## 技术方案与实现边界

| 部分 | 建议选型 | 职责 |
| --- | --- | --- |
| 桌面外壳 | Tauri 2 + Rust | 窗口、文件访问、系统集成及可靠保存 |
| 应用界面 | Svelte + TypeScript | 项目导航、搜索、设置和视图组织 |
| 编辑器 | CodeMirror 6 | 文本、选区、编辑事务、撤销和语法扩展 |
| 数学公式 | KaTeX | 公式排版与局部错误提示 |
| 持久化 | 本地 Markdown + 少量配置 | 保存正文、项目关联及界面偏好 |

Tauri 使用系统提供的 WebView，Windows 上使用 WebView2，有利于缩小应用分发体积。实际内存和启动表现取决于界面、编辑器及运行环境，需要测量。安装方案应说明 WebView2 运行时依赖，不能把运行时体积从统计中隐去后宣称软件整体极小。[Tauri 进程模型](https://v2.tauri.app/concept/process-model/)

CodeMirror 提供视口渲染和内容装饰机制，可用于实现复选框、Markdown 就地预览和公式展示。但接近 Typora 的光标、选区、输入法和块结构编辑体验仍需专门实现与验证。[CodeMirror 系统指南](https://codemirror.net/docs/guide/)

KaTeX 覆盖常见数学表达式，具体支持的命令及限制以官方列表为准。[KaTeX 支持范围](https://katex.org/docs/supported.html)

### 模块职责

编辑器负责唯一的当前文档状态和编辑历史。应用界面通过明确命令请求插入任务、切换完成状态、移动列表项、切换折叠或定位文本，不能自行复制编辑器内部文本作为第二份可编辑状态。排序命令校验源条目与目标边界，并在一次事务中移动完整源文范围；拖动预览不修改文档，提交前若文档已变化且不能可靠映射，则取消此次拖动。

任务识别与视图投影从文档语法树生成，负责列表项边界、嵌套关系、完成状态以及可见范围。待办、归档和搜索使用同一套任务语义，避免各自解析导致结果不一致。首版任务解析集中在编辑器侧，不在 Rust 中重复实现另一套 Markdown 任务解析器。

拖动范围与折叠范围复用同一语法树中的列表项边界，覆盖普通列表与任务列表，不通过屏幕可见行或逐行正则推断所属内容。折叠投影与完成过滤共同决定可见范围，界面状态映射负责让折叠跟随条目移动。

项目层管理文件关联、当前项目和各项目的界面状态。聚合视图中的索引只用于查询和定位，可以从源文件重建，不成为另一份正文来源。

文件层负责读取、按序保存、外部修改检测和恢复。只有文件层访问磁盘，任务投影不直接执行文件写入。编辑操作不通过同步磁盘访问阻塞输入。

### 保存与外部编辑

采用自动保存，并提供手动保存入口。文件写入通过同目录临时文件、适当刷新和平台支持的原子替换完成，具体行为需要在 Windows 上验证；失败时保留内存中的修改并显示准确状态。

保存请求按文档顺序处理，旧快照不能晚于新快照落盘。程序退出和异常恢复需要覆盖尚未写入主文件的修改；恢复数据属于编辑恢复用途，不作为永久任务数据库。

监听外部修改。内存文档未修改时可以加载外部内容；存在未保存修改时保留双方内容并提供差异处理入口，不静默覆盖。文件监听用于及时发现变化，保存前仍需检查已加载的磁盘基线，避免只依赖监听事件。

界面偏好与项目配置和 Markdown 正文分别保存。逻辑归档不依赖额外的完成时间字段，首版不展示无法从原文恢复的完成日期分组。

## 性能策略与验证目标

性能工作重点是控制编辑热路径和渲染范围：

- 当前文档采用一个编辑器实例，避免为每条任务创建独立编辑器。
- 按语法变化增量更新任务关系和可见范围，不在每次输入后重新解析并渲染所有项目。
- 只为可见区域及必要邻近区域构建昂贵的预览内容，公式按需渲染并缓存结果。
- 项目切换按需加载正文，后台索引分批处理，不一次挂载所有项目的文档视图。
- 文件保存与搜索索引更新合并频繁请求，并保证最新状态最终落盘。

初始验收场景为 20 个项目，当前文档包含 5,000 条任务，并混合长正文、代码和公式。测试前固定参考设备、文档大小、嵌套深度、公式数量及 WebView2 版本，以便比较结果。

| 指标 | 初始目标与测量边界 |
| --- | --- |
| 普通输入反馈 | P95 小于 16 ms，从输入事件到对应内容可见 |
| 勾选反馈 | 小于 50 ms，从点击到完成态可见；归档过渡时长单独记录 |
| 冷启动 | 约 1 秒进入可输入状态，安装依赖过程不计入启动但需单独说明 |
| 内存 | 记录包含 WebView 相关进程的总占用、稳定值及峰值，原型阶段确定预算 |

这些数值是工程目标；当前测量与验收边界见 [验收检查](验收检查.md)。遇到大文档瓶颈时，应根据采样区分解析、布局、公式渲染和磁盘开销，再决定优化位置。

## 实施顺序与验收

### 第一阶段：验证编辑内核

构建最小桌面原型，完成 Markdown 连续输入、就地预览、任务列表、嵌套正文、代码与公式、列表标记与任务复选框拖动排序、三角折叠展开、勾选及撤销。

重点验证中文输入法、Enter 语义、跨任务选择、批量粘贴和长任务归档。使用真实清单结构作为样例，确认预览及勾选不会重写无关原文。编辑手感通过后再扩展周边界面。

拖动与折叠验收覆盖：普通列表、有序列表和任务的行首控件；悬停显示与反复折叠展开；包含正文、代码、公式和隐藏子项的整体移动；嵌套条目同级排序；过滤视图落点与源文位置一致；无效落点及 Esc 取消；一次撤销恢复整次排序；折叠不修改源文；复选框单击完成与拖动排序正确区分，拖动成功或取消均不误触完成，三角按钮独立切换折叠。

### 第二阶段：完成日常使用闭环

加入多项目、已有文件关联、项目状态记忆、待办与归档视图、全部待办、搜索、自动保存、外部修改检测和恢复。

验收覆盖：切换项目不丢草稿；跨项目搜索定位正确；父子任务完成和恢复不隐藏未完成内容；撤销只影响当前项目；重启后文件状态正确；外部修改和保存失败时内容可找回。

同时验证项目切换及重启后的折叠恢复、外部编辑后的安全匹配、搜索自动展开祖先、排序保存后重新打开的内容与顺序，以及归档过滤与折叠叠加时的焦点可达性。

### 第三阶段：性能与视觉打磨

按固定的大文档场景测量输入、归档、启动、项目切换和内存表现，处理已确认的瓶颈。完成浅色与深色主题、键盘操作、窄窗口布局、减少动态效果及焦点稳定性验证。

首版交付包含可安装的 Windows 应用、上述核心功能、使用说明和可复现的性能测量记录。云同步、多人协作、复杂看板、提醒系统和插件平台不纳入首版范围；独立归档文件与项目多文档支持留待实际使用后确定。
